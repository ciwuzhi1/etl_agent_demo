## B. 三个关键概念（大白话）

**"ExecutionRun vs SeaTunnel JobId"是什么关系？** ExecutionRun 是平台的"执行档案"，包含谁发起的、哪个版本、什么时间、用了哪些凭据、产生了多少行数据、质量如何；SeaTunnel JobId 只是引擎那边的临时工号。平台用 ExecutionRun.id 作为稳定主键，JobId 只存在 submitted_at 之后，且可能因引擎重启而失效。

**"运行时监督"监督什么？** 不是监督人，是监督执行过程中的资源消耗：记录数是否超预算（默认 1000 万行）、字节数是否超限（默认 10GB）、是否超时（默认 1 小时）、输出是否异常放大（sink_rows/source_rows > 2.0）、错误率是否过高（reject_rate > 0.5）。一旦触发阈值，立即做出缓解决策（暂停/取消/隔离）。

**"原子发布"怎么做到原子？** Doris 有两张表：`clean_orders_tmp`（临时表）和 `clean_orders`（正式表）。执行时先写临时表，质量检查通过后，用 `ALTER TABLE clean_orders REPLACE WITH TABLE clean_orders_tmp` 一次性切换，要么全成功要么全回滚，不会出现"写了一半用户就看到脏数据"的情况。

## C. 这一章的坑

| 编号 | 坑 | 证据 | 处置建议 |
|---|---|---|---|
| P10-1 | **e2e Profile 未启动**：Docker Compose 的 mysql-e2e/doris/seatunnel 容器默认关闭 | `infra/compose.yaml` 里这些服务都在 `e2e` profile 下；当前只起了 postgres + redis | 本章先用 mock adapter 测试，实机验证等你决定启用 e2e 后再做 |
| P10-2 | **SeaTunnel REST API 认证未配置**：Zeta 引擎可能需要 token 或 basic auth | 参考实现 `zeta_adapter.py` 有 `api_key` 参数，但 `.env` 里没有对应配置项 | 先在 config.py 加 `seatunnel_api_key` 占位，默认 None；本地开发可跳过认证 |
| P10-3 | **Doris 原子发布需要特殊权限**：REPLACE TABLE 操作需要 ADMIN 角色 | Doris 文档明确说明只有 ADMIN 才能执行表替换 | 执行账号需用 ADMIN 角色，或在 Doris 侧配置专门的 publish 账号 |
| P10-4 | **Celery Beat 需要单独进程**：worker 不会自动执行周期任务 | `worker.py` 里定义了 beat_schedule，但需要 `celery -A ... beat` 单独启动 | 教学环境可在 worker 进程加 `--beat` 参数，生产应分离 |
| P10-5 | **OpenTelemetry Collector 未部署**：observability.py 配置了 exporter 但没有接收端 | 参考实现导出到 `http://localhost:4317`，但 demo 环境没有 OTel Collector | 本章先配置但不启用，等需要分布式追踪时再部署 Collector |
