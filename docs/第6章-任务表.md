## 一句话概括本章

第 5 章把异构文件变成受管数据源，本章给 **AI 生成的 HOCON 配置加一道确定性门禁**：在审批前逐一校验生成的 LocalFile/HDFS/JDBC/Doris/Hive 块是否精确匹配已画像的 Profile 拓扑、路径、Schema、凭据占位符和保存模式——防止模型"看起来数量对但读错表/写错库/换路径"。

关键边界一句话：**官方 CLI 只能验证配置语法可解析，不能证明模型没偷换容器内文件、没重复读取同一张表、没用通配符投影导致缺列；因此控制面必须在审批前用确定性比较封死所有 fail-open 缺口。**

## B. 三个关键概念（大白话）

**"确定性比较"比的是什么？** 不是比"大概像不像"，而是逐字符比对：路径必须一字不差、格式必须 json/csv 等枚举值、编码必须 UTF-8、字段名和类型必须集合相等（大小写无关）、凭据必须是 `${CONNECTION_...}` 占位符而非真实密码。任何一项对不上就抛 `DomainError`，不给模型"差不多就行"的空间。

**"拓扑门禁"防的是什么？** 防止模型用"数量对但内容错"的配置蒙混过关。例如 Profile 选了 2 张 MySQL 表，模型生成 2 个 Jdbc Source 但都读同一张表；或者没选 HDFS 却凭空多出一个 HdfsFile 块。所以要先数清楚每个 connector 的期望数量，再逐一匹配具体内容，缺一不可。

**"快照不含样本和凭据"为什么重要？** `profile_contracts()` 生成的快照会持久化到 `quality_contract` JSON 列，供后续审计和回放。如果带着脱敏样本，审查页面可能泄露敏感值；如果带着凭据占位符映射，攻击者可能推断出密钥结构。所以快照只保留"哪些列、什么类型、哪张表"这类结构元数据。

| 通过条件 | 判据 |
|---|---|
| 本章测试全绿 | 贴用例数（应为 17，不谎称其他数字） |
| 迁移链衔接 | `alembic current` = `heads` = 我们的 `0006`；`alembic check` 输出 `No new upgrade operations detected` |
| 快照不含敏感信息 | `profile_contracts()` 返回的字典里无 `masked_sample` / `credential_placeholders` / `connector_contract` |
| 拓扑门禁 fail-closed | 零期望连接器时额外生成块会抛 DomainError；重复 Source 会被拒绝 |
| 受管文件路径锁定 | 模型不能把 `/data/file-assets/asset-1/normalized.jsonl` 换成其他路径；字段类型漂移会被拒 |
| HDFS 占位符冻结 | `fs.defaultFS` / `remote_user` 必须是 `${CONNECTION_...}` 格式，不能是真实 URI |
| 数据库端点唯一匹配 | 两个 Jdbc Source 必须分别匹配两个不同 Profile 的 query；重复读同一张表会被拒 |
| 目标 Schema 精确对齐 | Doris Sink 的 SQL 投影必须显式列出所有目标列（禁止 `*`），缺列/多列都会抛错 |
| ruff / mypy strict | 全通过（含 `ruff format --check`） |
| ❌ 不写通过的两项 | ① Agent Graph 集成调用（P-4，属第 8 章）；② Pipeline 审批前置条件（P-4，属第 9 章） |
